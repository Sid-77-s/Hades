01 / PROJECT OVERVIEW
Problem Statement
Today's AI assistants are optimized for conversation. Real work still gets pushed back onto the user.
THE GAP
• AI can explain what to do, but often stops before the actual work.
• Users must repeatedly plan, execute, verify, and report progress.
• Complex tasks cross multiple tools: files, shell, browser, research, documents.
• Users need an assistant that can act with context — without turning every action into a permission dialog.
WHAT HADES CHANGES
Give HADES an outcome.
HADES decides how to get there, delegates work to specialized workers, uses Linux capabilities, verifies the result, and returns with the outcome.
LESS SUPERVISION
MORE EXECUTION

06 / DATA
Data Set Used
No custom training dataset is required for the current application prototype.
CURRENT APPROACH
NONE — NO PROPRIETARY TRAINING DATASET
• HADES uses foundation models through configurable model providers.
• Task execution can use live system state and tool outputs rather than a pre-collected training corpus.
• Research capabilities can retrieve current web information when enabled.
• User context and memory are used as application state, not as a training dataset.
Future versions could incorporate domain-specific evaluation datasets and task traces to improve reliability.

07 / LINUX INTEGRATION
Why Linux?
The hackathon target is an AI-powered application operating at the Linux application layer.
CONTROL
Direct access to the shell, filesystem and processes gives HADES a real execution environment.
COMPOSABILITY
Linux tools can be chained into workflows without forcing every capability into one monolithic AI.
OPEN ENVIRONMENT
The application can work with the developer's existing tools, files and workflows.
Windows + WSL can be used as the development/test environment; the target experience is HADES running as a Linux application.
