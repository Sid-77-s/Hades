Page 1 — Architecture Overview
Chapter Overview
Hades is not a single AI model. It is a coordinated intelligence composed of multiple specialized layers that work
together while presenting a single, unified experience to the user.
Architecture Philosophy
• Hide internal complexity.
• Expose only one persistent intelligence.
• Separate conversation from execution.
• Be model-agnostic.
• Support future expansion.
High-Level Architecture
The user interacts with one brain, while Hades coordinates many internal systems invisibly.

Page 2 — Core Components
Partner Brain
Responsibilities: conversation, reasoning, clarification, memory retrieval, alignment, and mission creation.
Inputs: user conversation, memory, active missions.
Outputs: clarified mission, questions, mission lock decision.
Executive Brain
Responsibilities: planning, delegation, worker selection, tool orchestration, progress monitoring, and recovery.
Mission Engine
Responsible for mission lifecycle, priorities, dependencies, constraints, success criteria, and mission state transitions.

Page 3 — Workers & Tools
Workers
Workers are specialized execution capabilities such as coding, research, writing, design, planning, and analysis.
Workers are implementation details. Users never choose workers.
Tool Layer
• Browser
• Terminal
• Git
• File System
• VS Code
• APIs

Worker Lifecycle
Workers never communicate directly with users. All outputs pass through Hades.

Page 4 — Memory & Review Engine
Memory Layers
Session Memory - current conversation.
Mission Memory - mission state.
Long-Term Memory - projects, preferences, goals, history, lessons learned.
Review Engine
Every worker output is validated for correctness, completeness, safety, alignment, and mission requirements.
Retry Logic
Nothing reaches the user without passing review.

Engineering Principles
• Every module has one responsibility.
• Components communicate through well-defined interfaces.
• Internal complexity is hidden.
• Models are replaceable.
• Memory is centralized.
• Review is mandatory.
• Conversation precedes execution.
Future Architecture
The architecture should support local models, cloud models, multi-device synchronization, autonomous scheduling,
plugin ecosystem, custom workers, and distributed execution.
